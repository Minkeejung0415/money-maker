# Plan 20-01: Leakage-Safe Historical Tactical Dataset

## Objective

Create a reproducible training table of historical senior international matches whose baseline and tactical features are reconstructed strictly from information available before kickoff.

## Tasks

<task type="auto">
  <name>Task 1: Define the historical row and provenance contracts</name>
  <files>alpha/data/ingestion/wc_tactical_history.py, tests/unit/data/test_wc_tactical_history.py</files>
  <action>Introduce typed row, exclusion, and dataset-metadata contracts. Include event ID, kickoff, competition, teams, score, baseline probabilities and goal rates, seven symmetric tactical components, profile sample depths, source timestamps, red-card/context flags, and exclusion reason. Version the feature schema. Keep team-name normalization centralized through the existing WC alias helpers.</action>
  <verify>Run `pytest tests/unit/data/test_wc_tactical_history.py -q`; fixtures prove serialization round trips, duplicate event IDs collapse deterministically, and malformed rows fail closed.</verify>
  <acceptance>The dataset contract is explicit, versioned, auditable, and contains every field needed to reproduce training and exclusions.</acceptance>
</task>

<task type="auto">
  <name>Task 2: Build rows with strict as-of joins</name>
  <files>alpha/data/ingestion/wc_tactical_history.py, scripts/build_wc_tactical_dataset.py, tests/unit/data/test_wc_tactical_history.py</files>
  <action>Enumerate and deduplicate completed senior international events from cached/free ESPN schedules. For each target, rebuild both tactical profiles using only events whose completion precedes kickoff, then compute the existing no-tactics baseline and tactical component vector. Exclude insufficient samples, missing scores, future-data contamination, red-card-distorted matches when controls are unavailable, and unsupported competitions. Write deterministic JSONL or Parquet plus a metadata manifest under the WC cache namespace.</action>
  <verify>Run the focused tests plus a small fixture build twice and assert byte-identical rows/manifest; add a test where a future match with extreme statistics cannot affect an earlier row.</verify>
  <acceptance>No row can observe its own or a later match, all exclusions carry reasons, and reruns over unchanged cache data are deterministic.</acceptance>
</task>

<task type="auto">
  <name>Task 3: Add coverage and holdout diagnostics</name>
  <files>scripts/build_wc_tactical_dataset.py, scripts/validate_wc_tactics.py, tests/unit/engines/test_validate_wc_tactics.py</files>
  <action>Add CLI summaries for discovered, eligible, excluded, development, and holdout counts; date/competition coverage; profile depth; missing-stat reasons; and class/score distributions. Hard-code the declared World Cup holdout boundary in metadata and prohibit training exports from including holdout rows. Exit nonzero for schema errors or leakage, but report an unmet 200/50 sample gate as a deployment-blocked result rather than fabricating readiness.</action>
  <verify>Run `pytest tests/unit/data/test_wc_tactical_history.py tests/unit/engines/test_validate_wc_tactics.py -q` and a cached-data dry run of `python scripts/build_wc_tactical_dataset.py --report-only`.</verify>
  <acceptance>The report makes coverage limitations visible and the holdout cannot enter a development export.</acceptance>
</task>

## Verification

- Focused tests pass.
- Determinism and future-leakage fixtures pass.
- Real cached-data report reaches the minimum sample gate or records deployment as blocked.

## Output

A versioned historical dataset and manifest suitable for chronological training without contaminating the World Cup holdout.
