# Phase 37 Plan 02: Local MLB Player Stats Database

<objective>
Add the first local MLB player-stat database layer that can ingest raw daily CSV-style rows, store them locally, and compute cumulative plus rolling derived stats for moneyline features.
</objective>

<tasks>

1. Add a local database module.
   - File: `alpha/data/ingestion/mlb_player_database.py`
   - Action: create a small API for loading raw daily batting, pitching, bullpen/team relief, lineup, and absence rows.
   - Acceptance criteria:
     - Supports in-memory/unit-test use without network.
     - Uses deterministic schemas and source/date metadata.
     - Stores or exports to DuckDB/parquet when available; if DuckDB is unavailable, falls back to inspectable local parquet/CSV-style data without failing tests.

2. Normalize raw daily rows.
   - File: `alpha/data/ingestion/mlb_player_database.py`
   - Action: normalize input dictionaries from CSV-style headers into internal raw component rows.
   - Acceptance criteria:
     - Batter rows preserve raw components such as hits, at-bats, walks, total bases, home runs, RBI, plate appearances, and game date.
     - Pitcher rows preserve raw components such as earned runs, innings pitched, runs, hits allowed, walks, strikeouts, pitches, batters faced, and game date.
     - Relief/bullpen rows can be keyed by team and date.

3. Compute derived stats locally.
   - File: `alpha/data/ingestion/mlb_player_database.py`
   - Action: add pure functions for formulas from raw components.
   - Acceptance criteria:
     - ERA = earned runs / innings pitched * 9.
     - AVG = hits / at-bats.
     - OBP, SLG, WHIP, K/9, BB/9, HR rate, and basic batting value can be computed when components exist.
     - Divide-by-zero and missing components produce explicit missing/default outputs, not crashes.

4. Add cumulative and rolling windows.
   - File: `alpha/data/ingestion/mlb_player_database.py`
   - Action: compute season-to-date and rolling 7/14/30 day summaries from appended daily logs.
   - Acceptance criteria:
     - Rolling windows use only rows before or on the target date according to the caller's pregame leakage policy.
     - Unit tests prove appending a new daily stat row changes derived cumulative stats, e.g. a pitcher allowing 3 earned runs in 4 innings changes ERA from raw components.

5. Add tests.
   - File: `tests/unit/test_mlb_player_database.py`
   - Action: cover normalization, formula computation, append behavior, rolling windows, missing values, and optional DuckDB/parquet behavior.
   - Acceptance criteria:
     - Tests do not require internet access.
     - Tests do not rely on large external data files.

</tasks>
