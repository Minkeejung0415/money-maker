# Phase 37 Plan 03: Database-Fed MLB Live Features and Suppression

<objective>
Wire the local player-stat database into live MLB moneyline inference so the scanner can use richer starter, lineup, bullpen, and absence context while clearly suppressing betting picks when data confidence is weak.
</objective>

<context>
Read before implementing:

- `.planning/phases/37-mlb-series-variance-player-database/37-CONTEXT.md`
- `.planning/phases/37-mlb-series-variance-player-database/37-RESEARCH.md`

</context>

<tasks>

1. Extend live player feature construction.
   - File: `alpha/data/ingestion/mlb_live_player_features.py`
   - Action: add an optional database-fed path that merges starter, lineup, bullpen, and absence features into the existing starter-only features.
   - Acceptance criteria:
     - Existing starter-only behavior remains available as fallback.
     - Feature keys align with `PLAYER_FEATURE_SETS` where feasible.
     - Missing lineup/bullpen data sets the existing missing flags instead of pretending confidence is high.

2. Add data freshness/source metadata.
   - Files: `alpha/data/ingestion/mlb_live_player_features.py`, `scripts/mlb_scanner.py`
   - Action: attach source, last updated date, component coverage, and confidence metadata to `game["player_features"]` or scanner context.
   - Acceptance criteria:
     - Scanner output can explain whether a game used named starters, team fallback, database lineup, bullpen data, or missing data.
     - Same-series repeated probabilities can be diagnosed from printed context.

3. Enforce suppression policy.
   - File: `alpha/engines/sports/mlb_model.py`
   - Action: ensure uncertainty flags include stale/missing database features and low lineup confidence.
   - Acceptance criteria:
     - Research probabilities are still returned.
     - `pick_eligible` is false when required player-data gates are weak.
     - Existing artifact validation behavior remains unchanged.

4. Update scanner wiring.
   - File: `scripts/mlb_scanner.py`
   - Action: add optional CLI/config hooks for loading local player database inputs, while keeping default runs functional.
   - Acceptance criteria:
     - The scanner can run without local CSV/database files and labels fallback.
     - When local database files exist, enriched features are merged before `MLBModel.predict(game)`.
     - `--individual-only` output shows relevant feature context.

5. Add tests.
   - Files: `tests/unit/test_mlb_live_player_features.py`, `tests/unit/test_mlb_scanner.py`, `tests/unit/engines/test_mlb_artifact_gate.py`
   - Action: cover database-fed features, fallback labels, suppression, and scanner output context.
   - Acceptance criteria:
     - Missing lineup confidence suppresses picks.
     - Fresh starter + lineup + bullpen data keeps pick eligibility available when artifact gates allow it.
     - Tests remain network-free.

</tasks>
