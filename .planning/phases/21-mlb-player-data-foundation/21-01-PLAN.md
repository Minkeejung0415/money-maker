<objective>
Add an additive MLB player-data foundation module that can normalize canonical game rows, game-player slot rows, player ID mappings, unmatched-player reports, and mocked day-of player context without touching the existing v1.3 team-only moneyline model.
</objective>

<must_haves>
- Preserve `alpha/engines/sports/mlb_training.py` and the current v1.3 `FEATURE_NAMES` path unchanged.
- Put new code in `alpha/data/ingestion/mlb_player_data.py` and tests in `tests/unit/test_mlb_player_data.py`.
- Use `game_id` as the primary identity and carry doubleheader/game-number metadata.
- Keep missing starters, lineups, and unmatched IDs explicit through `confirmed`, `source`, `missing_reason`, and unmatched-report fields.
- Keep unit tests network-free through mocked/injected providers.
</must_haves>

<tasks>

1. **Create canonical row contracts**
   - Files: `alpha/data/ingestion/mlb_player_data.py`
   - Action: Add dataclasses or typed helpers for normalized game rows, player-slot rows, player-ID mappings, and unmatched reports.
   - Verify: Rows expose dict-compatible shapes with stable keys for Phase 22.
   - Acceptance criteria:
     - Game rows include `game_id`, `game_date`, `home_team`, `away_team`, `venue`, `status`, `game_type`, `doubleheader`, `game_number`, target/final score fields, starter IDs/names, `source`, `confirmed`, and `missing_reason`.
     - Player-slot rows include `game_id`, `team`, `side`, `player_id`, `player_name`, `batting_order`, `position`, `slot_type`, `source`, `confirmed`, and `missing_reason`.

2. **Implement game normalization**
   - Files: `alpha/data/ingestion/mlb_player_data.py`
   - Action: Add `normalize_games(raw_games)` that accepts StatsAPI-shaped schedule rows and returns deduplicated canonical game dicts sorted by date/game ID.
   - Verify: Unit tests cover final games, scheduled games, missing starters, duplicate game IDs, and doubleheader metadata.
   - Acceptance criteria:
     - Duplicate rows with the same `game_id` collapse deterministically.
     - Missing probable starters preserve the game row with explicit missing fields.
     - Completed games expose `home_win` only when final non-tie scores exist.

3. **Implement player-slot normalization**
   - Files: `alpha/data/ingestion/mlb_player_data.py`
   - Action: Add `normalize_player_slots(raw_slots, game_id=None)` for lineup/starter rows from generic Retrosheet/boxscore/StatsAPI-like dictionaries.
   - Verify: Unit tests cover confirmed lineups, projected/unknown slots, missing player IDs, batting-order normalization, and starter/pitcher slots.
   - Acceptance criteria:
     - Lineup rows preserve player identity and confirmation state.
     - Unknown/projected rows are allowed only when tied to a known `game_id`.
     - Invalid rows without game identity are skipped rather than silently inventing IDs.

4. **Implement ID mapping and unmatched reporting**
   - Files: `alpha/data/ingestion/mlb_player_data.py`
   - Action: Add `build_player_id_map(rows)` and `report_unmatched_players(slots, id_map)` supporting MLBAM, Retrosheet, Baseball Reference, and FanGraphs key placeholders.
   - Verify: Unit tests cover matched IDs, name-only fallback rows, duplicate aliases, and unmatched output.
   - Acceptance criteria:
     - The ID map can be keyed by all known external IDs and normalized player names.
     - Unmatched slots are reported explicitly with game/team/player/source context.
     - No fuzzy matching silently mutates player identity.

5. **Implement day-of player context assembly**
   - Files: `alpha/data/ingestion/mlb_player_data.py`
   - Action: Add `fetch_day_of_player_context(date_str=None, schedule_provider=None, lineup_provider=None, injury_provider=None)` using injected providers and default StatsAPI-compatible schedule behavior.
   - Verify: Unit tests mock all providers and prove no live network is needed.
   - Acceptance criteria:
     - Return shape includes `games`, `game_player_slots`, `injuries`, and `unmatched_players`.
     - Provider failures return partial context plus source/missing flags rather than raising.
     - ESPN injury data is treated as fallback context, not canonical player identity ground truth.

6. **Protect existing baseline**
   - Files: `tests/unit/test_mlb_player_data.py`
   - Action: Add a regression test or import check proving the new module does not alter `alpha.engines.sports.mlb_training.FEATURE_NAMES`.
   - Verify: Focused MLB tests pass.
   - Acceptance criteria:
     - Existing v1.3 feature schema remains exactly eight team-state fields.

</tasks>
