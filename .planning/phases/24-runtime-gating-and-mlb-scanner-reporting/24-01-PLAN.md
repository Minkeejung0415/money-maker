# Phase 24 Plan: Runtime Gating and MLB Scanner Reporting

## Goal

Make MLB runtime output safely player-aware only when validated and sufficiently certain, while visibly falling back to v1.3 or market-implied probabilities otherwise.

## Implementation Steps

1. Update `MLBModel` artifact loading.
   - Search v1.8 and v1.3 artifact locations.
   - Validate v1.8 metadata, gates, schema, features, model, and calibrator.
   - Reject legacy non-bundle artifacts.

2. Add v1.8 prediction path.
   - Read required features from `game["player_features"]` or top-level game fields.
   - Apply model and calibrator.
   - Attach source label, confidence, feature context, metrics, and pick eligibility.
   - Fall back when required features or uncertainty gates fail.

3. Add runtime reporting.
   - Expose `runtime_report()` with source, artifact version, metrics, promotion gates, coverage, and confidence-gated report fields.
   - Preserve existing prediction keys for compatibility.

4. Update scanner reporting.
   - Print v1.8, v1.3 fallback, or market-implied labels per game.
   - Show fallback/suppression reasons and high-confidence player-aware context.
   - Exclude suppressed player-aware games from moneyline parlay construction.

5. Add tests.
   - Valid v1.8 artifacts load and score precomputed player features.
   - Invalid v1.8 artifacts fall back to v1.3 or market-implied.
   - Uncertainty flags suppress v1.8 picks.
   - Legacy non-bundle artifacts are rejected.
   - Scanner-facing prediction fields are present and stable.
